# clignotte

A small command-line note keeper backed by a local SQLite database. Notes are
grouped into notebooks, support due dates, and can be styled with single-char
prefixes that the renderer turns into ANSI colour codes.

The binary is named `note`; the project (and database) are named `clignotte`.

## Features

- Multiple notebooks, with one always flagged as the current one
- Optional due dates, with overdue notes highlighted in red
- Mark notes as done (closed), important, bold, or blinking yellow
- Full-text search across all notes (SQLite FTS5)
- Bulk import from a text file (one note per line), an audio file
  (one note per Whisper segment, with timestamps), or an image/PDF
  (one note per non-empty OCR line via Tesseract)
- Attach local files or URLs to notes; optionally copy files into the
  clignotte storage folder
- Each note carries a UUID for sync with external services
- Compact, terminal-width-aware listing
- Stored as plain SQLite at `$XDG_DATA_HOME/clignotte/notes.db`
  (typically `~/.local/share/clignotte/notes.db`)

## Build

Requires Qt 6 with the `core` and `sql` modules, plus the SQLite driver.
On Arch Linux: `pacman -S qt6-base`.

Optional tools (detected at runtime; `note --help` shows which are available):

| Tool | Package | Used for |
|---|---|---|
| `whisper` | `python-openai-whisper` | Audio transcription |
| `tesseract` | `tesseract tesseract-data-eng` | Image/PDF OCR |
| `pdftoppm` | `poppler` | PDF-to-image conversion (required for PDF OCR) |

```sh
qmake6
make
```

The build aborts with a clear error if you run the Qt 5 `qmake` by mistake.
The resulting binary is `./note`.

An Arch `PKGBUILD` is provided under [`pkg/archlinux/`](pkg/archlinux/PKGBUILD).

## Install

```sh
qmake6 PREFIX=/usr/local         # default; pass PREFIX=/usr for system-wide
make
sudo make install                 # respects DESTDIR for staged installs
sudo make uninstall               # removes everything install put down
```

`make install` places:

| File | Destination |
|---|---|
| binary | `$PREFIX/bin/note` |
| bash completion | `$PREFIX/share/bash-completion/completions/note` |
| zsh completion | `$PREFIX/share/zsh/site-functions/_note` |
| fish completion | `$PREFIX/share/fish/vendor_completions.d/note.fish` |
| license | `$PREFIX/share/licenses/clignotte/LICENSE` |

The completion scripts are generated by running the freshly-built binary as a
post-link step, so they always match what `note completions <shell>` emits.

## Usage

Running `note` with no command prints all notes grouped by notebook:

```sh
note
```

By default, listings (`list`, `today`, `week`, `search`, `bytag`, and the no-arg
view) only show open notes. Pass `--all` to include closed ones — useful for
reviewing what's been done. Notebooks whose notes are all closed disappear from
the no-arg view but reappear with `--all`.

`note --help` lists every command. The full reference:

| Command | Description |
|---|---|
| *(no command)* | display notes grouped by notebook |
| `list` | display notes in a single-line table |
| `today` | open notes due today or overdue, across all notebooks (sorted by due date) |
| `week` | open notes due in the next 7 days (today + 6), across all notebooks |
| `bytag` | display notes grouped by tag (one section per tag; multi-tagged notes appear in each) |
| `add <text>` | add a note to the current notebook; prints the new note's id on stdout |
| `add -` | read note text from stdin (one note, full input); prints the new note's id |
| `edit <id>` | open `$VISUAL` / `$EDITOR` (fallback: `vi`) on note `<id>` |
| `move <id> <title>` | move note `<id>` to notebook `<title>` (created if absent, current notebook unchanged) |
| `import <path>` | import notes from a text file (one per line), audio file (one per Whisper segment), or image/PDF (one per OCR line) |
| `import -` | import notes from stdin (one note per non-empty line) |
| `close <id>` | mark note `<id>` as done |
| `due <id> <date>` | set due date `yyyy-MM-dd` for note `<id>` |
| `important <id>` | mark note `<id>` as important (red) |
| `bold <id>` | mark note `<id>` as bold (inverted) |
| `blink <id>` | mark note `<id>` as blinking yellow |
| `normal <id>` | strip any styling prefix from note `<id>` |
| `delete <id>` | delete note `<id>` |
| `notebooks` | list all notebooks |
| `notebook <title>` | switch to or create notebook `<title>` |
| `close-notebook <title>` | mark every open note in notebook `<title>` as done |
| `search <query>` | full-text search across all notes (FTS5 syntax) |
| `attach <id> <path>` | attach a local file or URL to note `<id>` |
| `attach <id> <path> --copy` | copy the file to clignotte storage then attach |
| `attachments <id>` | list attachments for note `<id>` |
| `detach <attach_id>` | remove an attachment by its id |
| `tag <id> <name>...` | add one or more tags to note `<id>` (case-insensitive, idempotent) |
| `untag <id> <name>...` | remove tags from note `<id>` |
| `tags` | list all tags in use, with usage counts |
| `tags <id>` | list the tags on note `<id>` |
| `export <dir>` | write all notes to `<dir>` as one `<uuid>.md` file per note |
| `sync <dir>` | reconcile notes from `<dir>` into the database (additive merge by default; `--delete` for mirror semantics) |
| `completions <shell>` | emit a shell completion script (`bash`, `zsh`, or `fish`) to stdout |

### Examples

```sh
note notebook work          # switch to (or create) the "work" notebook
note add Call the bank      # add a note to the current notebook
note edit 3                 # open $EDITOR on note 3
note move 3 personal        # move note 3 to the "personal" notebook
note due 3 2026-06-01       # give note 3 a due date
note important 3            # highlight note 3 in red
note close 3                # mark note 3 as done
note search "bank OR loan"  # FTS5 boolean search
note today                  # what's due today (or overdue) across all notebooks
note week                   # what's due in the next 7 days across all notebooks
note bytag                  # show notes grouped by tag
note list                   # one-line-per-note overview
note import bullets.txt     # one note per non-empty line
note import meeting.opus    # transcribe audio, one note per segment
note import scan.png        # OCR image, one note per line
note import report.pdf      # OCR PDF (requires poppler for pdftoppm)
note attach 5 spec.pdf      # store path to spec.pdf on note 5
note attach 5 photo.jpg --copy  # copy photo.jpg into clignotte storage
note attachments 5          # list attachments on note 5
note detach 2               # remove attachment id 2
```

### Piping and scripting

`clignotte` plays nice with the rest of your shell.

```sh
echo "captured from a pipe" | note add -    # one note; prints the new id
ID=$(note add "buy milk") && note tag "$ID" shopping   # capture id and chain
git log --oneline -10 | note import -        # bulk capture, one note per line
note list --json | jq '.[] | select(.due_date)'   # filter open dated notes
note today --json | jq -r '.[].id' | xargs -n1 note close  # close everything overdue
note search "bank" --json                    # FTS results as JSON
```

`--json` is supported on `list`, `today`, `week`, `search`, and the no-arg view.
Each note is emitted as `{id, notebook, text, due_date, done_at, attachments}`,
with `due_date` and `done_at` nullable (ISO strings).

ANSI styling is automatically suppressed when stdout is not a terminal (e.g.
piped to `grep` or redirected to a file). Set `NO_COLOR=1` to disable colors
on a tty as well.

### Tags

Notebooks group notes by location ("where it lives"); tags are orthogonal
labels for what a note is *about*. A note has one notebook and zero-or-more
tags. Tags are case-insensitive and idempotent — re-adding an existing tag
is a no-op.

```sh
note tag 3 home shopping       # attach two tags at once
note untag 3 shopping           # remove one
note tags                       # see all tags + counts
note tags 3                     # see tags on a specific note
note list --tag home            # filter by tag
note list --tag work --tag urgent   # AND across multiple --tag (drill down)
note list --notebook work       # filter by notebook (exact title, case-sensitive)
note list --notebook work --tag urgent  # combine — AND across both
note today --tag work           # combine with agenda
note bytag --notebook work      # narrow tag groups to one notebook
note search "bank" --tag finance    # combine with FTS
```

The `--json` output of `list`/`today`/`week`/`search` includes a `tags`
array on each note. Tags vanish automatically when their last note is
deleted (no orphan-cleanup needed).

### Sync via git

`note export` writes one `<uuid>.md` file per note into a directory; `note sync`
reconciles such a directory back into the database. Combine with git for
multi-machine sync:

```sh
# one-time setup
mkdir ~/clignotte-sync && cd ~/clignotte-sync
git init && git remote add origin <your-remote>

# push local changes
note export ~/clignotte-sync
git -C ~/clignotte-sync add -A && git -C ~/clignotte-sync commit -m "sync"
git -C ~/clignotte-sync push

# pull remote changes
git -C ~/clignotte-sync pull
note sync ~/clignotte-sync           # additive: new files create notes,
                                     # changed files update them, missing files ignored
note sync ~/clignotte-sync --delete  # mirror: also delete local notes whose files are gone
```

Each `.md` file has a small key:value header (uuid, notebook, created_at,
due_date, done_at, tags) followed by a blank line and the note body. Editing
a file by hand is supported — the next `sync` picks up your changes.

UUIDs are the durable identity across machines. Notes existing pre-sync get
a UUID assigned on first `export`. Two machines that independently created
the "same" note before sync was set up will end up with two distinct notes.

If two machines edit the same note between syncs, `git pull` surfaces a
normal merge conflict in the `.md` file. Resolve in git, then `note sync`.

**Not synced:** attachments. The `attachment` table is local-only — syncing
absolute paths across hosts would just create dangling references, and
copied files are stored under your local data dir. Use `rsync` / Syncthing
for the binary side if you need it.

### Shell completions

`note completions <shell>` writes a completion script to stdout. Common installs:

```sh
# bash — quick try
eval "$(note completions bash)"
# bash — persistent (per-user)
note completions bash > ~/.local/share/bash-completion/completions/note

# zsh — persistent (file must be in $fpath, named _note)
note completions zsh > "${fpath[1]}/_note"

# fish — persistent
note completions fish > ~/.config/fish/completions/note.fish
```

Completion covers: subcommands, shell names after `completions`, file paths
after `import` and `attach`, and the global flags `--json`, `--copy`,
`--help`, `--version`. Note ids and notebook titles are not yet completed
dynamically.

### Status icons in `list` / `search`

Each row shows a single status character. Priority (highest wins):

| Icon | Meaning | Style |
|---|---|---|
| `✓` | done (`close`d) | italic |
| `!` | overdue (due date is in the past) | red background |
| `~` | blink-marked | blinking yellow |
| `*` | important-marked | red |
| `>` | bold-marked | inverted |
| `·` | open / no styling | default |

### Styling prefixes

Styling is encoded as a single leading character in the note's text:

- `!foo` → important
- `*foo` → bold
- `~foo` → blink yellow

The mark/normal commands manage these prefixes for you, but you can also type
them directly when adding a note (`note add !urgent fix`). Switching styles
replaces the prefix without losing content; `normal` strips it.

### Search syntax

`search` uses SQLite FTS5 and supports its query language:

- `pdf` — single token
- `"exact phrase"` — phrase
- `bank OR loan` — boolean OR (also `AND`, `NOT`)
- `migr*` — prefix match

Results are ordered by FTS rank (most relevant first).

### Importing notes

`note import <path>` dispatches based on the file extension:

- **Text files** (any non-audio extension): each non-empty line becomes a note
  in the current notebook. Whitespace-only lines are skipped; styling prefixes
  (`!`, `*`, `~`) at the start of a line are honoured. The whole import runs in
  a single SQL transaction, so large files are fast and partial failures roll
  back.
- **Audio files** (`mp3`, `wav`, `ogg`, `oga`, `opus`, `m4a`, `mp4`, `flac`,
  `aac`, `webm`, `wma`, `amr`, `mka`, `3gp`, `mpeg`, `mpga`): `clignotte`
  shells out to [`whisper`](https://github.com/openai/whisper)
  (`pacman -S python-openai-whisper`) with `--output_format json` and creates
  one note per transcribed segment, prefixed with the segment start time as
  `[HH:MM:SS]`. Whisper's stderr (model loading, progress) is forwarded so you
  can follow long transcriptions.

  If `whisper` isn't on `$PATH`, you'll get a clear hint pointing at the
  package name. Auto language detection is left to Whisper; pre-process or
  rename your file if you want to force a specific language for now.

- **Image files** (`png`, `jpg`, `jpeg`, `tiff`, `tif`, `bmp`, `pnm`, `pbm`,
  `pgm`, `ppm`, `webp`): `clignotte` shells out to
  [`tesseract`](https://github.com/tesseract-ocr/tesseract)
  (`pacman -S tesseract tesseract-data-eng`) and creates one note per
  non-empty output line. Tesseract's stderr (model loading) is forwarded.
  Install additional language packs (`tesseract-data-fra`, etc.) for
  non-English documents.

- **PDF files**: same as image OCR, but `clignotte` first converts each page
  to a PNG using `pdftoppm` from
  [`poppler`](https://poppler.freedesktop.org/) (`pacman -S poppler`), then
  OCRs each page with `tesseract`. Both tools must be on `$PATH`; missing
  either produces a clear install hint.

`note --help` shows which optional tools are present on your system.

### Attachments

A note can have any number of attachments — local file paths or URLs — stored
in the database (files are not copied by default).

```sh
note attach 5 /path/to/file.pdf      # store the path
note attach 5 https://example.com    # store the URL
note attach 5 photo.jpg --copy       # copy into ~/.local/share/clignotte/attachments/
note attachments 5                   # list attachment ids, paths, and copy origins
note detach 3                        # remove attachment with id 3 (does not delete copied files)
```

Copied files are stored as `<uuid>_<original_filename>` inside the clignotte
attachments folder so names never collide.

### Terminal width

`list` and `search` adapt the text column to your terminal width via
`ioctl(TIOCGWINSZ)`, with `$COLUMNS` as a fallback (useful for piping). The
text column never shrinks below 20 characters.
